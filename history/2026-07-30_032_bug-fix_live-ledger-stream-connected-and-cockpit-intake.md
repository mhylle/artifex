# 2026-07-30 · 032 · bug-fix · The live ledger stream is connected, and a mission can be started from the cockpit

**What:** Shipped R14 (mission intake from Mission Control) and fixed three defects that only a real browser could surface — CORS (`main.ts`), unvalidated intake bodies (`fd345eae`), and a live ledger stream that was never connected (`b3b4e554`). Also transferred the frozen dossier's unbuilt scope into Tasktracker as **R14–R40, 85 acceptance criteria**, and set a goal charter (`docs/GOAL-full-system.md`).

**Why:** The owner asked to submit a mission through the UI and found there was no way to — the cockpit could only watch. Investigating that produced a much larger finding: the dossier's whole operator console, plus two of the three memory-fabric stores and both learning loops, had been deferred **in prose** (`packages/dashboard/CLAUDE.md`, the dossier) and never entered the system of record. `getProjectDoneness` only evaluates what Tasktracker knows, so all five pillars reported green against a scope that had quietly shrunk (`cd18baa0`).

**Details:**

- **R14 — intake from the cockpit.** Objective / success criteria / out-of-scope, refusal with a named reason before anything reaches the wire, auto-watch on accept, error surfacing. New `MissionIntake` service + `mission-intake.ts` schema in `shared-types` (it crosses the dashboard↔API boundary). Templates and styles extracted to `mission-control.html` / `.css` per the owner's new standing rule: **no inline `template:` or `styles:`**, recorded in both CLAUDE.mds and on the Dashboard architecture component.
- **CORS.** `main.ts` never called `enableCors`, so the browser blocked the intake POST at preflight. Twenty-five passing jsdom component tests were silent on it — jsdom does not enforce CORS. Left open deliberately; narrowing is for the security phase.
- **`fd345eae`.** `@Body() body: IntakeRequest` typed against a TypeScript interface, erased at runtime, so a malformed body died as `Cannot read properties of undefined (reading 'length')` — a 500 that told the operator nothing. Now validated against `MissionIntakeRequestSchema` (TypeBox, per ADR-0004 — no second validation dialect at the HTTP edge), returning a 400 naming every offending field. Ordered *after* the two human-readable guards so "present but empty" keeps its actionable sentence and no existing test was weakened.
- **`b3b4e554` — the big one.** `LedgerStreamService.onNotification` and `LedgerListener` were both complete and both well tested, and **nothing joined them**: no process anywhere opened a Postgres `LISTEN`. A mission ran end to end while a connected dashboard sat at "1 events"; reloading replayed all 19. Added `LedgerLiveBridge` (bootstrap-starts the listener on its own client — `LISTEN` is per-connection — with background retry, a `live` flag, and fail-safe bootstrap) and wired it in the composition root. Second half: the worker appended `result.trail` only *after* `runMission` resolved, so even a connected listener would have delivered one burst at the end; `runMission` gained an `onEvent` hook on its single `record()` funnel and the worker now appends through a serial promise chain as events happen.
- **Stale processes.** Four orphaned worker processes were found running simultaneously from earlier restarts. Also confirmed the built-in `DATABASE_URL` default (`5433`) is a *different project's* Postgres on this machine; the real one is `55432` per `.env`.

**Outcome:** All four R14 acceptance criteria satisfied and **verified in a real browser with Playwright** — refusal messages, submission with no shell involved, auto-watch, and the tree filling in live (14 events mid-flight, 16 at `delivered`, both tasks verified, zero console errors). The API now logs `[LedgerLiveBridge] live ledger stream connected` at boot, which had never appeared before. 281 tests green across the workspaces; every new distractor mutation-verified. Defects `04071ce9`, `fd345eae` and `b3b4e554` resolved. Logged a global learning: **unit tests cannot detect an uncalled function — assert the composition, not just the component.** Still open: `2e5eaece` (the planner emits duplicate subtasks — visible in the UI, both children carry the parent objective verbatim) and `cd18baa0` (closes when R14–R40 are built).
