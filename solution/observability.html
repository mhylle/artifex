Chapter 5 · Observability

Watching the swarm think

A swarm you cannot see is a swarm you cannot trust, steer, or debug. Observability in Artifex is not a bolt-on monitoring layer — it is the second consumer of the same audit substrate the Learning Agent feeds on: the machine learns from the ledger, and humans watch and steer through it, live, on a visual mission-control surface inspired by node-canvas tools like n8n.

Three principles

A view, never a second truth

The dashboard renders ledger events and nothing else. It holds no state of its own, computes no facts the ledger doesn't contain, and can therefore never disagree with the audit trail. If it's on screen, there is an event behind it.

Every pixel is drillable

Node → task → contract → verdicts → individual events: any visual element opens into the evidence beneath it. The dashboard's job is not to summarize away detail but to make the full depth reachable in two clicks.

Watching is also acting

Mission control is a cockpit, not a window. Humans approve escalations, answer clarifications, pause subtrees, top up budgets and turn the autonomy dial from here — and every such act is itself a ledger event, first-class and attributable like everything the agents do.

One substrate, three consumers

Mission control — the canvas

The centerpiece is a live node canvas in the n8n tradition: the mission's task graph laid out as connected nodes, executing left to right, each node wearing its state openly — with icon and label, never color alone. The mock below shows one mission mid-flight, drilled one level into the tree:

The five lenses

One dashboard, five ways of looking at the same ledger — switchable per mission, shareable as links, identical truth underneath:

1 · Canvas

The n8n-style task graph above: structure, states and flow. Collapse/expand subtrees; the breadcrumb drills through depth; heat mode tints nodes by budget burn or retry count when you need to see where effort pools.

2 · Workforce

Agent-centric: every specialist currently alive, grouped by category — which design and version, which task it holds, how long it's run, its live compliance rate. The "who is working right now" view, with lineage one click away.

3 · Timeline

Swimlanes per subtree: when tasks started, waited, ran, got reviewed, escalated. The lens that exposes stalls, review queues and the critical path — where wall-clock time actually went.

4 · Learning observatory

The swarm improving itself: experiments in flight with their pre-registered metrics, adoptions and reverts on the ratchet, library growth, per-category compliance trends, amendment petitions pending. Watching the institution evolve is a first-class view, not a log file.

5 · Ledger explorer

The raw substrate, queryable: filter by event family, error class, agent, criterion, time range. Where investigations end and where every drill-down from the other four lenses lands.

The cockpit — what a human can do from here

Mission control is where the autonomy dial cashes out. Every control below writes a ledger event with the operator's identity attached — the swarm's rule that nothing acts without leaving a trail applies to humans too:

ControlBehavior
Answer & approveThe attention queue surfaces everything waiting on a human: escalations that reached the ladder's top rung, clarification requests, flagged assumptions that started to matter, surrender-threshold confirmations, amendment ratifications. Each item shows its full context inline — the contract, the verdicts, what was tried — so deciding never requires an investigation.
Pause / resume / cancelAny node or whole subtree. Pausing is graceful — running workers finish their current attempt; cancellation triggers the same accounting a surrender does, so cancelled work still teaches.
Budget grantsTop up a task or subtree from the mission reserve, or extend the mission budget itself (which may require requester approval per the dial). Grants are economic events — visible in every later cost analysis.
Turn the dial mid-flightTighten or loosen autonomy while a mission runs — e.g. drop to closely-supervised after a suspicious pattern, or release a smoothly-running mission to full autonomy. Takes effect at the next gate, never retroactively.
Nudge the recordAttach operator annotations to any task or verdict — context the Learning Agent will see when it mines this mission. Humans teaching the swarm through the same channel the swarm teaches itself.

Time travel

Because the ledger is append-only and complete, any past moment of any mission is reconstructable: drag the scrubber and the whole dashboard — canvas, workforce, budgets, inspector — renders exactly as it stood then. Functionally this gives three capabilities beyond curiosity: post-mortems replay a failure from before it was visible, watching the early-warning signs the risk register says to look for; before/after diffing compares any two moments — or the same mission slice before and after a learning adoption, which is how the Learning Observatory shows an improvement rather than asserting it; and honest demos — a delivered mission can be replayed for its requester end to end, which is the pedigree promise of Stage 6 made visible.

Functional requirements, summarized

  • Live streaming: the dashboard reflects ledger events as they land — running missions are watched, not polled into staleness.
  • Scale handling: the canvas stays legible at thousands of nodes — collapse by subtree, aggregate node badges ("142 tasks · 3 escalated"), breadcrumb drill-down, minimap navigation.
  • Two-click depth: from any visual element to its underlying events in at most two interactions.
  • Attention queue: one place listing everything that waits on a human, ranked by what it blocks; nothing addressed to a human may exist only as a buried event.
  • Symmetric acts: every human action available in the cockpit produces a ledger event with actor identity; there is no invisible steering.
  • Time travel: full reconstruction of any past dashboard state; diff view between any two moments.
  • Audience filtering: operator, requester and learning-observer views draw from the same events with entitlement filters — the requester's simplicity is a filter, not a separate pipeline.
  • No second truth: the dashboard persists nothing the ledger doesn't; deleting the dashboard loses no information.
