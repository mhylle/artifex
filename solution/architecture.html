Chapter 1 · Architecture

The standing structure

Artifex has four kinds of parts: a permanent meta-layer of four agents that runs the institution, a disposable execution plane manufactured per mission, a persistent memory fabric that is the system's accumulated intelligence, and a small immutable constitution that keeps the whole thing honest while it rewrites itself.

The four parts, briefly

Meta-layer — the permanent institution

Four agents exist before, during and after every mission: Orchestrator, Agent Creator, Reviewer, Learning Agent. They embody the system's only built-in competence: organizing work. Their playbooks — how to decompose, how to design agents, how to judge, how to learn — are versioned, evolvable assets, so the institution itself improves over time.

Full role descriptions in The Agents.

Execution plane — the conjured workforce

Per mission, a disposable plane of specialist workers grouped by task category, plus a Context Broker. Workers see nothing but their own contract; they hold no standing state; when the mission ends, the plane evaporates. What survives is their performance record — and, for the best designs, promotion into the library.

Memory fabric — the shared brain

Three stores with deliberately different rules. The Audit Ledger records everything, including failures — append-only evidence. The Asset Registry holds only what has earned its place: agent designs, decomposition templates, playbooks — a ratchet that only advances on measured wins. The Knowledge Commons holds validated facts about the world, with provenance and expiry. Detail in Memory & Learning.

Constitution — the unmodifiable core

A deliberately tiny set of rules the swarm cannot rewrite about itself: what success metrics mean, that review is independent of the reviewed, that the audit trail is complete and tamper-evident, that budgets bind. Everything outside it is fair game for self-improvement. The evidence for why it must exist is in Risks & Safeguards.

The constitution, precisely

The single most consistent finding across every self-improving system studied — Darwin Gödel Machine deleting its own hallucination detectors, frontier agents gaming visible scorers 43× more than hidden ones, autoresearch's frozen prepare.py being its most load-bearing property — is that a learner must not own the yardstick it is measured by. Artifex adopts the ambition of full self-modification and pairs it with a constitutional carve-out:

  • Metric definitions. What "task passed", "mission succeeded", and "value per effort" mean — the definitions, not the thresholds — are constitutional. The Learning Agent optimizes against them, never over them.
  • Review independence. A reviewing agent never shares design lineage with the agent it reviews, never sees an incentive tied to pass rates, and its verdicts cannot be edited after the fact. Workers never see the verification harness that will judge them.
  • Audit-trail integrity. Events are append-only, attributable, and complete. No agent — including the Learning Agent — can suppress, rewrite or filter what gets recorded.
  • Budget enforcement. Effort ceilings and floors bind mechanically. An agent cannot grant itself more budget; only the level above it can, and that grant is itself a logged, budgeted act.
  • The amendment protocol itself. The rule for changing the rules cannot be changed by the swarm.

One mission, one instance — one shared brain

Each mission runs in its own isolated instance: its own orchestration state, its own conjured workforce, its own working artifacts. No cross-talk between running missions. But all instances read from and report back to the same memory fabric, and one Learning Agent serves them all. Execution is isolated so that missions are clean, comparable experiments; learning is collective so that every mission makes all future missions better.

Communication rules

Work moves only through contracts. A task contract is the sole interface between levels of the tree. Parents speak to children by writing contracts; children speak to parents by delivering against them. There is no other channel for work.
Context moves only through the broker. A worker that needs more than its contract — a sibling's output, mission background, a fact from the commons — requests it from the Context Broker, which serves it, filters it to what the contract entitles the worker to see, and logs the exchange. No peer-to-peer chatter: emergent coordination is precisely the thing that made classic blackboard systems undebuggable, and mediated exchange is what keeps the audit trail complete.
Cross-cutting decisions are pinned at contract-writing time. When siblings' outputs must fit together — shared interfaces, naming, formats, conventions — the parent decides before fan-out and pins the decision into every affected child contract. Integration conflicts are prevented upstream, not discovered at fold-up. ("Actions carry implicit decisions, and conflicting decisions carry bad results" — the documented killer of naive parallelism.)
Reads parallelize; writes serialize. Any number of workers may read the same context concurrently. Tasks that produce or mutate a shared artifact are serialized within their subtree, with the parent as the single writer at fold-up.

The observability plane

One structural element sits deliberately beside the swarm rather than inside it: the observability plane. It subscribes to the audit ledger's event stream and renders it — live mission canvases, workforce views, budget burn, the attention queue of items waiting on a human — without owning any state of its own. Humans steer the swarm from here (approvals, answers, pauses, budget grants, dial changes), and each such act is written back as a first-class ledger event. Because it is a pure view over the fabric, it can also reconstruct any past moment of any mission. The full functional description, including the n8n-inspired mission-control dashboard, is in Observability.

Scope boundary of this description

This dossier describes functionality: what the parts are, what they do, and the rules between them. It deliberately does not choose models, runtimes, storage, protocols or infrastructure, and it defers security hardening and performance engineering — with one principled exception: wherever integrity of measurement is concerned (constitution, review independence, audit completeness), the functional design already takes a position, because there the research is unambiguous that integrity is functionality — a swarm that can grade itself kindly does not merely perform worse, it stops being improvable at all.
