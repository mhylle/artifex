Artifex · Latin for “the master craftsman” — the workforce that crafts itself

A workforce that does not exist
until the work arrives.

Artifex is a self-assembling, self-improving agent system. A permanent four-agent meta-layer takes any mission, shatters it into thousands of atomic, individually verifiable tasks, designs the minimal set of specialist agents needed to execute them — writing their instructions at runtime — verifies every task at both ends, folds the results back into one coherent outcome, and mines the complete audit trail of everything it just did to become measurably better before the next mission.

Version 1.1 · 22 July 2026 · Functional scope only — technology, security and performance intentionally deferred · Brainstorm outcome, Martin Hylleberg

The idea in one pass

Today's agent systems ship with a fixed cast: someone decides up front which agents exist, what they are good at, and how they cooperate. Artifex inverts this. The only permanent employees are four meta-agents — an Orchestrator that decomposes and integrates, an Agent Creator that designs the workforce, a Reviewer that verifies everything, and a Learning Agent that improves the whole institution. Everything else — every specialist that researches, writes, calculates, builds, translates, checks — is conjured on demand, categorized so a thousand tasks need perhaps a dozen agent designs rather than a thousand, and discarded or promoted based on how it actually performed.

The system is born knowing nothing about any domain. It knows only how to organize work: how to split it, contract it, staff it, verify it, assemble it, and learn from it. Domain expertise is not built in — it is a thing the swarm manufactures, and the good designs are kept.

What is actually new here

The workforce is designed at runtime

No predefined agent roster. The Agent Creator categorizes the mission's tasks, searches the library of proven designs, and writes system prompts for whatever specialists don't exist yet — reuse first, creation second.

Verification guards both ends

Review is not a final gate. Every task's atomicity is verified before execution (is this truly one responsibility?) and its completion is verified against a contract written at birth. The task graph itself is a reviewable artifact.

Constitutional self-improvement

The Learning Agent may rewrite anything about how the swarm works — prompts, playbooks, strategies, taxonomies — except the small constitutional core that defines how success is measured. It can propose amendments; it can never self-ratify them.

Six design pillars

1 · Atomize, then verify

Tasks are split to the smallest unit that carries exactly one responsibility and one testable outcome. Reliability at scale comes from per-step verification, not from hoping big steps go well.

2 · No work without a contract

Nothing executes without acceptance criteria, boundaries, stopping conditions and a budget — written before the work, by the level above. The mission itself is task zero and obeys the same rule.

3 · Permanence is earned

Agent designs, workflows and knowledge are ephemeral by default. Only measured, replicated, transfer-tested wins are promoted into the permanent library — and promotion tracks the performance of a design's whole lineage, not one lucky audition.

4 · Learn everything, game nothing

Two-speed learning: bounded hot-fixes during a mission, a rigorous science loop between missions. All of it runs outside the constitutional core, so the swarm can never optimize its own scorecard instead of the work.

5 · Everything leaves a trail

Every decision, delegation, verdict, retry and context exchange is a structured, attributable event. The audit trail is not compliance overhead — it is the substrate learning feeds on, and it doubles as the replay benchmark suite.

6 · Effort is a currency

Missions and tasks carry effort budgets — floors that prevent shallow work, ceilings that prevent runaway spawning. The fitness function of the whole system is value per unit of effort, not raw output.

Decisions locked in this brainstorm

DecisionChoice
Mission scopeTruly domain-neutral. No anchor domain; domain expertise is conjured like any other capability.
Decomposition driveMaximal atomization — one responsibility, one verifiable outcome per task. Atomicity is itself a verified property, and the Orchestrator holds a decompose-vs-delegate-whole gate for sequential work.
IntegrationRecursive fold-up: each parent assembles and reconciles its children's outputs; the decomposition tree in reverse.
Definition of doneBorn with the task. Acceptance criteria are written into every contract at decomposition time; the Reviewer checks the contract.
Failure handlingEscalation ladder: feedback-retry → differently-designed agent → agent redesign → re-decomposition → human/surrender. Every rung logged, and the rung chosen is driven by the error class in the verdict.
Agent permanenceEarned. Designs start ephemeral; the Learning Agent promotes proven lineages into the library and down-weights weak ones (never hard-deletes).
Learning depthFull self-modification within a constitutional core: metric definitions, review independence, audit integrity and budget enforcement are immutable to the learner; amendments only via out-of-band ratification.
Human roleAutonomy dial per mission — from fully autonomous to closely supervised — plus escalation rules agents use when stuck, uncertain, or facing irreversible choices.
KnowledgeEarned knowledge commons: validated findings persist across missions with provenance, quarantine before promotion, curation and expiry.
Concurrency modelInstance per mission, shared brain: isolated execution, collective learning.
CommunicationContracts plus a mediated context broker. No free agent-to-agent chatter; every exchange is logged.
Learning cadenceTwo-speed: bounded inline hot-fixes during missions; the autoresearch-style science loop between them.
Mission intakeContract-first: no mission starts without testable success criteria, scope boundaries, an autonomy setting and a budget. The mission is task zero.
EconomicsBudgeted swarm. Effort budgets are floors and ceilings; the ledger records cost against value; learning optimizes value-per-effort.
ImpossibilitySurrender is a first-class outcome: partial results, precise blockers, and what would have to change — delivered as a dossier, and mined as premium learning material.
ObservabilityA cockpit, not a window: an n8n-inspired live mission-control dashboard rendered purely from the audit ledger — task canvas, workforce, budgets, attention queue — with time-travel replay, operator/requester/learning views, and human interventions logged as first-class events.
